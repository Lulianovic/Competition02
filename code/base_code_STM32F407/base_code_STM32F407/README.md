# 慧灌智控（HuiGuan Smart Irrigation）

> 面向设施农业的多源感知、可信诊断与自适应节水控制系统
> 基于 STM32F407ZG 的智能农业监测与灌溉控制项目

## 项目简介

### 背景

在设施农业中，作物生长环境会受到土壤含水量、空气温湿度、光照强度等多种因素影响。传统灌溉方式通常依赖人工经验或固定阈值控制，难以根据环境变化及时调整灌溉策略，也缺乏对传感器异常、通信中断及执行设备运行时间的有效管理。

本项目设计并实现一套基于 STM32F407ZG 微控制器的智能农业监测与灌溉控制系统：采集多种环境参数，结合数据有效性检查、灌溉需求评估和状态机控制，实现环境监测、自动灌溉、异常保护及运行记录等功能。系统以仿真平台为主要开发与验证环境，在有限周期内完成从传感器数据输入到控制指令输出的完整闭环，并通过对照实验验证控制策略的有效性。

### 目标

1. **多源环境监测**：采集土壤湿度、空气温湿度和光照强度，为决策提供依据。
2. **数据可信诊断**：对传感器数据进行范围检查、有效性判断和超时检测，识别异常并采取保护措施。
3. **智能灌溉决策**：以土壤湿度为主要依据，结合其他参数构建灌溉需求评分机制。
4. **安全闭环控制**：通过状态机管理水泵启停、最长运行时间、冷却间隔和故障状态，减少误动作与频繁启停。
5. **人机交互与运行记录**：通过 OLED 显示屏和串口终端展示环境数据、运行状态和决策原因。
6. **对照测试与效果评估**：将多参数决策策略与固定阈值策略对比，评估控制稳定性与故障处理表现。

### 定位

面向设施农业场景的嵌入式智能灌溉控制原型系统，当前阶段以仿真验证为主，重点验证控制算法、软件架构和异常处理机制，不直接将仿真结果等同于真实农田节水效果。

### 系统工作流程

```text
环境数据输入（土壤湿度 / 空气温湿度 / 光照强度）
        │
        ▼
数据采集与格式转换
        │
        ▼
数据有效性检查 ──异常──▶ 故障处理与安全保护
        │正常
        ▼
灌溉需求评估（两级判断：安全约束 + 需求评分）
        │
        ▼
状态机控制（IDLE / IRRIGATING / COOLDOWN / FAULT）
        │
        ▼
水泵控制与运行保护 + 串口/OLED 运行记录
```

## 硬件连接

- **土壤湿度 YL-69 (AO)** — PA0 (ADC1_IN0)：主控制依据
- **备用电压源** — PA1 (ADC1_IN1)：标定 / 验证用
- **空气温湿度 DHT11** — PB0：单总线
- **光照 BH1750** — PB8 / PB9：I2C（与 OLED 同总线）
- **串口 USART1** — PA9 / PA10：115200，CSV 日志 + 命令
- **继电器（水泵）** — PC0：DQ 控制
- **蜂鸣器** — PC1：故障报警
- **状态灯 LED** — PC2：按状态闪烁
- **OLED** — PB8 / PB9：英文界面

**继电器接线**：`VCC→5V+`、`GND→电池-`、`DQ→PC0`、`COM→5V+`、`NO→空`、`NC→水泵`（本模块为高电平触发，水泵接 NC，开泵 = PC0 低电平）。

**电源**：5V 电池只供继电器线圈与水泵；3.3V 供传感器与 OLED；两路仅在 GND 共地。

## 串口命令

波特率 115200。命令与参数间用逗号分隔，**行尾不要带空格**。

- `HELP`：打印命令列表
- `SOIL,<0~100>`：注入土壤湿度(%)，仅 `MODE,TEST` 生效
- `AIR,<℃>,<%>`：注入空气温度、湿度，仅 `MODE,TEST` 生效
- `LIGHT,<lux>`：注入光照强度，仅 `MODE,TEST` 生效
- `MODE,AUTO`：真实传感器模式
- `MODE,TEST`：允许注入模拟数据
- `MODE,THRESHOLD`：固定阈值策略（默认）
- `MODE,SCORE`：多参数评分策略
- `FAULT,SOIL_TIMEOUT`：模拟土壤数据超时，触发数据无效故障
- `FAULT,CLEAR`：解除故障 + 清除注入

## 决策逻辑摘要

- **两级判断**：第一级安全约束（土壤湿度、数据有效、运行时长、冷却）优先；第二级综合评分。
- **固定阈值**：土壤 `< 30%` 开泵，`≥ 40%` 关泵，中间 30%~40% 为滞回区防抖。
- **多参数评分**：`S = 0.70·M + 0.10·T + 0.10·H + 0.10·L`，`S ≥ 60` 才开泵（土壤仍为主控，辅助参数不能绕过）。
- **状态机**：`IDLE → IRRIGATING → COOLDOWN → FAULT`。

### 评分公式

各分项先归一化到 0~100，`clamp01(x)` 表示将 x 限制在 [0, 1]。其中 `soil` 为土壤湿度(%)、`temp` 为空气温度(℃)、`humi` 为空气湿度(%)、`lux` 为光照强度。

- **土壤 M（权重 0.70）**：`clamp01((40 - soil) / (40 - 30)) × 100` —— 越干分越高
- **温度 T（权重 0.10）**：`clamp01((temp - 20) / (40 - 20)) × 100` —— 越热蒸腾越强
- **湿度 H（权重 0.10）**：`clamp01((60 - humi) / (60 - 20)) × 100` —— 空气越干分越高
- **光照 L（权重 0.10）**：`clamp01(lux / 20000) × 100` —— 光照越强蒸腾越强

综合评分（各分项加权和）：

```
S = 0.70·M + 0.10·T + 0.10·H + 0.10·L
```

权重与归一化区间均可在 `app_config.h` 中调整。

### 开泵判定（顺序不可颠倒）

1. **安全闸门（第一级）**：只要 `土壤% ≥ 40`（停止阈值），**直接不开泵**，评分再高也无效。
2. **第二级**：
   - `MODE,THRESHOLD`（默认）：仅看 `土壤% < 30` 开泵，**空气温湿度、光照完全不参与**。
   - `MODE,SCORE`：看 `S ≥ 60` 开泵——温/湿/光三项最多占 30% 评分，只能微调开泵的土壤临界点，不能越过土壤闸门。

**示例**（空气 40℃ / 60%RH / 212 lux）：T = 100、H = 0、L ≈ 1，开泵点约在土壤 `≤ 32.9%`；若空气更干或光照更强，该临界点会上移。

## 安全保护

- 单次开泵最长 **10 s** → 触发 `PUMP_OVERTIME` 并**锁定**，需 `FAULT,CLEAR` 解除。
- 停泵后 **冷却 5 s** 才允许再开。
- 传感器数据无效/超时 → `DATA_INVALID`，禁止自动灌溉，恢复后自动回 `IDLE`。

## 运行日志

每 0.5 s 输出一行 CSV，字段依次为：
`时间戳,来源,土壤%,土壤raw,备用raw,温度℃,湿度%,光照,土壤有效,空气有效,光照有效,模式,策略,评分,泵(0/1),状态,故障,原因`

## 构建

使用 `arm-none-eabi-gcc` + Makefile（`make` 构建，`make clean` 清产物后重新构建）。修改 `APPLICATION/app_config.h` 后需重新构建并重新加载生成的 `main.hex / main.bin`。
